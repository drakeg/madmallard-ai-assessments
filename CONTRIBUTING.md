# Contributing

1. Create an issue with problem, acceptance criteria and sprint assignment.
2. Branch from `main` using `feat/`, `fix/`, or `docs/`.
3. Add tests for changed behavior; run `python3 -m pytest -q`.
4. Update documentation and changelog for user-visible changes.
5. Open a PR describing risks, test evidence and rollback. Do not merge failing CI.
6. Request review and merge only after approval. Delete merged feature branches.

Use conventional commits (`feat:`, `fix:`, `docs:`, `chore:`). No client data or secrets in issues or fixtures.
